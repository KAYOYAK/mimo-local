feat: 补回「中断回合」—— chat-demo 的停止按钮之前只停前端

按「功能只能多不能少」逐条比对旧界面和 chat-demo，发现一处真缺失：

## 问题

旧界面 stop_round() 会调 ag.abort_session() 真正中断 MiMo Code 的回合。
chat-demo 的停止按钮只做 `controller.abort()`（前端断 fetch），
**后端完全不知道** —— 界面显示「已停止」，9B 还在烧 GPU、工具还在跑。

## 修法（不改前端）

桥检测客户端断开，把它当成「用户按了停止」：

- `_sse_safe()`：写 SSE 失败（BrokenPipe/ConnectionReset）返回 False 而不抛
- `on_event` 里一旦写不出去，**立即**调 `ag.abort_session()`

**为什么必须立即**：`send_message` 是阻塞的（最长 900 秒），
如果在 finally 里才 abort，用户点了停止还是得等这一轮跑完 —— 等于没中断。

## 顺带补的功能对照

旧界面独有的（全部已可访问）：
  选择目录 / 启动引擎 / 停止引擎  -> 菜单 → 引擎
  状态灯 / 项目路径 / 上下文占用   -> 状态栏
  自检 / 断言 / 诊断 / 换模型 / 日志 -> 菜单 → 工具
  关于                          -> 菜单 → 帮助
  中断回合                      -> 桥（本次补）

和 chat-demo 重合的（留新的）：
  会话列表 / 图片上传 / 发送停止 / 思考过程 / 复制 -> chat-demo 自带
  工具调用展示 -> 桥转成 `OK bash {...}` 文本（卡片变一行，更省地方）
