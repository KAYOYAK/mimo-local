v1.0.3: 修 review 指出的一个回归 + 四处同源缺陷

## P0 回归：界面不显示模型正文
   `_on_part` 的 echo 过滤里多了一个**无条件的 return**（12 空格缩进，
   在外层 if 体内）——任何 text part 都在创建文本块之前被丢掉。
   SSE 和 _reconcile 两条路都走这个函数，所以两条都不显示文字：
   能看到「思考中」和工具卡片，然后就是空白。
   下面那段超长截断成了死代码。

   根因是我上一轮用 PowerShell 正则批量替换时留下了原来的 return。
   而当时的自检和声明断言全在查「某个字符串在不在源码里」，
   没有一条和「用户能不能看见回答」有交集。

   **修法不只是删掉那个 return**：
   - 渲染决策抽到 core/render.py 的纯函数 decide(part, echoes)
   - 自检新增「渲染管线」检查（34 项，原来 29）：
     直接喂假 part 给 decide，验证正文/思考/工具会被渲染、
     synthetic/step-start/空文本会被过滤、echo 只吞一次、超长会截断
   - 这条检查不需要 GPU、不需要起引擎、不需要窗口

## 同源缺陷：config.current_model() 只接了一半
   新增了 current_model()/current_mmproj()，但只有两处读它，其余仍读默认值：
   - tools/switch_model.py    「←当前」标记永远指默认模型；
                              选回默认模型时 chosen == cur 直接 return，
                              settings.json 不变 → 切不回去
                              结语还写着「config.py 已更新」（实际写的是 settings.json）
   - core/hardware.py         model_size_gb(config.CHAT_MODEL) —— 换成更大的模型后
                              自动减层仍按 6.02 GB 估算，可能不触发 --fit on → OOM
   - tools/report.py          诊断报告描述的模型和正在跑的不是同一个
   - tools/selfcheck.py       自检显示同样的旧信息
   全部改成 current_model() / current_mmproj()。

## 其他修复
   - kill_pid 加身份校验：pid 会被 Windows 回收，盲杀可能杀掉无关进程。
     先用 tasklist 确认映像名是 llama-server 再杀。
   - _reconcile 跨线程改 UI 状态：worker 线程直接改 self.items，
     而 GUI 线程的 _flush 定时器正在读。改成走 bridge 发回 GUI 线程。
   - pick_dir 没清 _echoes：换项目后 echo 计数会串。加一行 clear()。
   - stop_round 提前设「就绪」：busy 还没清，状态栏在撒谎。
     改成由 send() 的 finally 统一收尾。
   - 版本号两个来源：installer.py 写死 VERSION = "1.0.0"，config.py 是 1.0.2
     → 安装器界面和「应用和功能」显示旧版本。改成从 config.py 解析。

## claims 的四条「假绿」
   方向对，但强度不够 —— 全部是「字符串存在性」，改个名字或加个注释就能骗过：
   - claim_no_orphan       有函数不代表有人调用 → 加「kill_pid( 在 ui_qt 出现 ≥2 次」
   - claim_abort           按钮存在不代表接线 → 查 clicked.connect(self.stop_round)
   - claim_audit_log       注释里提一句就过 → 查 _audit_command 的定义和调用
   - claim_64k_estimate    返回值在集合里就算过 → 抽 derive_ctx/derive_kv 纯函数，
                           表驱动验证 11 个显存档位的边界
   验证方法：故意把 clicked.connect 改掉，断言立刻报不符（17/18）。

   另外两条新断言：版本号全仓库只能有一个来源、README 提到的 --开关 必须存在。

## 打包后路径验证（tools/verify_packaged.ps1）
   这一轮修的东西（settings.json 位置、--ocr 子命令、生成的 AGENTS-ocr.md、
   卸载串）每一条都有 frozen 变体，而 claims 的 frozen 分支只有打包环境才走。
   仓库里原本没有任何东西能证明「打包后是好的」。
   新增脚本，三条断言全部不需要显卡：
     1. --claims 必须 0 退出，且 frozen 分支真的走到
     2. --selfcheck 不能有 [缺失]
     3. --ocr 测试图 必须产出 .md（附带一张 97 KB 的真实收据图）
   脚本自己踩了一个坑：PyInstaller onefile 有父子两个进程，
   Start-Process -Wait 只等父进程，子进程可能还在写文件 → 改成轮询等文件。
