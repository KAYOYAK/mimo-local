v1.0.18: 修「新对话第一句回答不显示」

用户反馈：发第一句话，回答一点都不显示；切换到别的对话再切回来就显示了。
不是时间问题（等很久也一样），每个对话都会，发「你好」都会。

根因（我自己上一版引入的）：
  echo 过滤的前缀匹配太宽。
    _echoes["你好"] = 1
    模型回答 "你好！有什么可以帮你的？"
    → txt.startswith("你好") == True → 被当成用户消息的 echo 吞掉
  再加上重复计数（shown 和 payload 各记一次 → 变成 2），连吞两次，
  回答彻底不显示。切换对话走的是历史加载（不经过 echo 过滤），
  所以一切回来又显示了。

修法：
1. core/render.py 的匹配规则改严格：
   - 精确相等（txt == key）            → 吞（用户消息 echo）
   - 只有 key 是「完整 payload」
     （含【用户的问题】/【用户发的图片：】）  → 才允许包含匹配
     这是为了带图片的场景：payload 比显示的「（看图）」长
   - 其余一律不吞
2. ui_qt.send()：只有带图片时才把 payload 加进 echo。
   没图片时 payload == 用户原话，上面已经记过一次，再记就重复。

实测：
  用户 echo "你好" 被吞 ✓
  回答 "你好！有什么可以帮你的？" 显示 ✓（修复前被吞）
  完整 payload 仍被吞 ✓（带图片场景没破）
  第二次回答显示 ✓

自检加两条（「用户 echo 会被吞」「回答不会被误吞」），共 41 项。
