v1.0.4: 修 echo×reconcile 重复渲染 + 门禁测的不是产品代码

## 必须修 1：用户自己的问题会重复出现
   _reconcile 判断「这个 part 渲染过没有」用的是 set(self._by_id.keys())，
   但被 echo 吞掉的用户 part 从来没进过 _by_id。于是：
     send() → _echoes[问题] = 1
       → SSE 送来用户 part → decide 命中 echo → 吞掉（不进 _by_id），计数减到 0
       → POST 返回 → _reconcile 发现 pid 不在 _by_id → 重新 emit
       → decide：_echoes 已经是 0 → 当成正文渲染
   结果：每轮结束后，用户自己问的那句话会以「模型回答」的样式再出现一次。

   这是修 echo 过滤时，把「按文本计数的 echo」和「按 pid 判断已渲染」
   两套机制拼在一起才出现的 —— 两边各自都对，合起来漏了。

   修：加 self._seen 集合，被吞掉的 part 也记成「见过」；
   _reconcile 用 set(self._by_id) | self._seen 判断。

## 必须修 2：门禁测的代码不是产品跑的代码
   plan_chat() 里自己抄了一份 KV 判断（if config.CHAT_KV / elif vram <= 0 /
   elif vram < 9），而 claims 表驱动测的是 derive_kv —— 两份逻辑。
   今天阈值恰好一致所以没现病，但哪天只改一边：claims 全绿而行为不变，
   或者产品变了门禁还绿。
   修：kv = config.CHAT_KV or derive_kv(vram)，两边是同一个函数。
