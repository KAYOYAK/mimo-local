v1.0.14: 三个子进程都会收尸（修「端口被占用启动不了」）

用户反馈：打开一次就启动不了，报「端口 4096 已被占用」，
提示用任务管理器结束 mimo.exe。但任务管理器里那两个 MiMoLocal.exe
是 PyInstaller onefile 的父子进程（1 MB 解压器 + 62 MB 应用），**正常**。

真正的根因：上次异常退出（崩溃/强杀/直接关窗口失败）留下的
mimo serve 和 llama-server 没跟着退，一直占着端口。
而原来**只有 OCR 有 pid 文件**，聊天引擎和 mimo serve 都没有 ——
所以根本没法收尸。

修法：
- config 加 CHAT_PID_FILE / AGENT_PID_FILE
- EngineSpec 加 pid_file 字段，Engine.start() 写、stop() 删
- AgentServer.start() 写、stop() 删
- 程序启动时和退出时都把三个 pid 都收一遍

顺带挖出一个更严重的坑：
  _pid_is_llama() 里用 subprocess.run(..., text=True) 读 tasklist。
  中文 Windows 上 tasklist 输出是 GBK，解读时抛 UnicodeDecodeError
  （实测 0xd0），异常被 except 吞掉 → 身份校验永远返回 False
  → **收尸功能等于没写**（上一版就是这样，只是没暴露）。
  改成 encoding="mbcs", errors="replace"。

实测收尸流程（test：起引擎 → 丢弃对象模拟崩溃 → 收尸）：
  起引擎后 pid 文件写入 32000，身份校验 True，8080 占用
  丢弃对象后进程还活着、端口还占着（模拟真实崩溃）
  kill_pid → True，8080 释放，pid 文件删除   [PASS]

自检加「子进程收尸」3 项（39 项）。
