fix: 多轮对话会失忆 —— session key 里带了消息数量

## 根因

桥把 Anthropic 的 messages 数组映射到 MiMo Code 的 session，
映射键算成：

    key = f"{seed[:200]}|{len(messages)}"

`len(messages)` 每多一轮就变，所以**每轮都新建一个 session**。
模型看到的是一个空的新会话 —— 表现就是失忆：

    第1轮「记住数字 7429」  -> session A
    第2轮「刚才的数字是多少」-> session B（空）-> 答不上来

单轮测试完全看不出来（每轮都是 1 条消息），只有连问两句才暴露。

## 修法

改成只哈希第一条消息：

    key = sha256(第一条消息).hexdigest()[:16]

实测三轮：
    第1轮 key=256c79f7…  session=ses_…0186ffe   "记住了"
    第2轮 key=256c79f7…  session=ses_…0186ffe   "7429"    <- 记得
    第3轮 key=82a6c044…  session=ses_…d8a43ffe   "1"       <- 另一个对话，隔离正确

已知局限（写进 README）：两个不同对话如果第一条消息一模一样，
会共用一个 session。彻底解决需要前端带会话 id，但 Anthropic 的
请求头/请求体里都没有这个字段，chat-demo 也没加。

## 顺带修的

`_report_usage` 一开始放进了 _BridgeHandler 却用 self.on_usage 访问
AgentBridge 的属性，两处报 AttributeError（回归时暴露的）。
现在它是 Handler 的方法，用 self.bridge.on_usage。
