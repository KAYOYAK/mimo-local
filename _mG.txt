test: 桥的回归测试（单轮 / 多轮 / 中断）

三个场景各对应一个真踩过的坑，跑一条命令全验：

    python tools/test_bridge.py              # 三个都跑
    python tools/test_bridge.py -s multi     # 只跑一个

  1. single  工具调用能穿过桥
     - 坑：part→block 映射写错时工具调用静默消失
     - 任务要用「不调工具就猜不到」的（echo MIMO_TOOL_OK_9917），
       问「列出目录有哪些文件」模型会直接从上下文答，测不到映射

  2. multi   第 2 轮记得上文
     - 坑：session key 里带 len(messages)，每轮新建 session → 失忆
     - 加一条反证：换个对话不该知道这个数字

  3. abort   断连后后端真停
     - 坑：只断前端 fetch，9B 继续烧 GPU、工具继续跑
     - 做法：读几个事件就硬断 socket，8 秒后查 /session/{id} 的 busy

## 写测试时又踩到一个

工具调用现在走 thinking block（可折叠），所以检查工具调用必须看
thinking_delta。第一版测试只读 text_delta，明明工具跑了却判成 FAIL。
